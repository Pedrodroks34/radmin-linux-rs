## 2. Source of Disagreements (where Phase 2.4 reports disagreed internally)

- **Slot arithmetic base error:** Report `05` computed Table A slots using nominal base `0x0051FFAC` but the constructor's actual vptr is `0x0051FFB4` (4 bytes / one slot higher). This shifted every Table A slot target by one entry (R2, R3). Reports `05` and `17` inherited this error.
- **Table B/C slot-22 off-by-four:** Report `05` listed Table B/C slot 22 at `0x51E5C4`/`0x51E544` (value `0x00451090`) but `0x51E5C4`/`0x51E544` is slot **20** (`+0x54` from base), while slot 22 is `+0x58` = `0x51E5C8`/`0x51E548` (value `0x00450FC0`). A 4-byte slot-index mistake (R5, R7).
- **Release semantics:** Report `07` described `FUN_004731E0` as "decrement"; disassembly shows `LOCK XCHG [edi+0x20], esi` with esi=0 — an **exchange to zero**, not a decrement (R10).
- **`FUN_00473210` role:** Report `07`/`17` predicted "decrement-and-destroy-if-zero"; actual code performs two `InterlockedExchange` operations (zero +0x20, set +0x24=1) plus a helper call (R11).
- **Indirect vs direct deallocation call:** Report `08` described `CALL [0x00500CA6]` (indirect through memory); the actual instruction is a direct relative `CALL 0x00500CA6`, and `0x00500CA6` is code, not an IAT slot (R13).
